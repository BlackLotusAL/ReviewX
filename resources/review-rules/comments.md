# ReviewX 评论规则 v1

## MR 评论规范（PRD 6.3）

每条 Finding 的 body 使用以下中文 Markdown 骨架，生成具体、可执行的意见；不要保留占位符。英文标识符、仓库路径和代码保持原样。

````markdown
### 🟠 Major: <问题标题>

**问题描述**：

- 严重级别：Major
- 标签：`#tag`
- 简述：<问题说明>

**问题位置**：`path/to/file:line-range`

```language
<相关代码>
```

**影响分析**：

- **直接后果**：<直接后果>
- **影响范围**：<影响范围>
- **触发条件**：<触发条件>

**解决方案**：

<可执行的解决方案；数量按问题实际需要，不要求两个>

```language
<必要时提供示例代码>
```

**预防措施**：

- <预防同类问题的措施>
````

Severity 展示映射：

| JSON severity | 标题展示 | 正文严重级别 |
| --- | --- | --- |
| `fatal` | 🔴 Fatal | Fatal |
| `major` | 🟠 Major | Major |
| `minor` | 🟡 Minor | Minor |
| `suggestion` | 🟢 Suggestion | Suggestion |

- 根据实际问题选择 severity；骨架中的 Major 仅为示例，不是指定等级。标题信号灯、英文展示等级、正文严重级别和 JSON severity 必须保持一致。
- 问题位置使用仓库相对路径，并尽量给出行号或明确代码范围。
- 影响分析说明直接后果、影响范围和触发条件，结合已读取的 source、未修改调用方和 base 给出可核对例子。
- 解决方案数量由问题决定，不要求固定为两个。代码示例仅在有助于说明问题或方案时提供，无需为凑骨架添加代码块。
- 预防措施应与当前问题直接相关。
- 以上为生成指导；宿主不解析或校验章节数量、标签、代码块或解决方案数量，也不改写 body。
