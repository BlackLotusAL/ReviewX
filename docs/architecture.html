01

系统组件与调用方向

浏览器只访问本地 Web API；Runtime 是业务协调入口，外部能力由适配器提供。

蓝线：调用 / 请求；响应沿原路返回紫色：原生 AI 执行绿虚线：文件读取 / 持久化

两个独立的业务通道

检视通道一次执行一个 attempt，按 FIFO 取队列。发送通道一次发送一条 Finding，用户确认后调用 CodeHub；可与检视同时进行。评论发送结果未知时不自动重试，避免重复评论。

本地服务与模型服务

ReviewX 和每轮 OpenCode 服务都使用本地 loopback。OpenCode 通过随机凭据访问，模型请求由其已配置的服务处理。模型与版本不设品牌白名单，但必要接口和代理配置必须可用。

接口与信任边界

浏览器读取 GET /api/state 只同步本地状态，不刷新 CodeHub。创建检视使用 POST /api/reviews，恢复使用 POST /api/reviews/resume，发布使用 POST /api/attempts/{id}/findings/{ordinal}/publish。

状态变更请求校验 Host、同源 Origin 和 JSON Content-Type。仓库文件、MR 文本与规则是检视输入，不能授权编辑、执行脚本或发布评论。

02

一次检视的真实执行顺序

下列主路径从用户请求开始，区分模型执行、进程收尾、持久化与工作区删除。

  1. 入队前冻结规则
    Runtime / rules

    读取安装包 resources/rules 的直属 Markdown，冻结后随 attempt 持久化；规则加载失败时不创建任务、不归档上次结果。加载成功才加入全局 FIFO。

  2. 取队列与读取 MR
    Runtime / CodeHub

    任务进入 reviewing；读取当前 MR 一次，确认仍开放，记录标题、描述和源 / 目标分支。不在检视结束后重新查询 MR 作为结果接受条件。

  3. 固定 Git 输入
    GitPreparer

    fetch 后固定 sourceSha、targetSha 与唯一 merge-base。宿主创建 source / base 工作树、changes.diff、scope.json，并读取变更路径祖先目录中的仓库规则。

  4. 启动原生会话
    OpenCodeReviewer

    写入 review-context.json 和权限配置，启动 serve --pure；检查健康接口与代理配置后创建主会话。配置关闭项目配置加载、默认插件、外部技能、LSP 和格式化等能力。

  5. 检视、复核与输出
    OpenCode

    主代理按提示词分发四个任务、去重并逐候选复核；最终文本先写入任务目录。解析 JSON，必要时最多进行一次无工具修复，再执行路径容错和固定渲染。

  6. ① 尝试进程收尾
    适配器 finally

    结束 SSE、请求会话 abort（最多 3 秒）、触发进程树终止，并等待退出确认（最多 10 秒）。已有结果但退出未确认时，返回结果及 cleanupPending；没有结果时抛出清理异常。

  7. ② 保存报告和状态
    ReportStore / StateStore

    确认未被取消后，先写不可变报告目录，再登记 attempt 的结果、正文及报告引用。状态登记成功后才有可发布结果；只有孤立报告文件并不代表任务成功。

  8. ③ 清理或暂停
    Runtime

    进程退出已确认则删除工作区，删除失败记警告。cleanupPending 时保留待清理工作区，保存可用结果后暂停队列。普通任务结束后继续后续 FIFO。

界面阶段 cleaning_up 不是精确的时序边界：代码在适配器返回后设置该阶段，再进入 saving_report。进程收尾与工作区删除必须按上面的两个实际调用位置理解。
连接恢复、进度与时间预算

SSE 只更新活动说明和观察指标，不承担结果验收。生成 POST 响应丢失后，每次查询原会话状态与消息，间隔约 1 秒；连续三次查询失败则退出，不重发生成请求，不重放事件。

Runtime 整轮预算 60 分钟；普通控制请求 30 秒；生成请求使用整轮信号。单次 Git 命令预算 10 分钟。停止取消活动会话和进程树，取消后不追加格式修复、不登记新的可发布结果。

仅保留已复核问题；必需工作未完成时按提示词报告 incomplete

这是提示词约定的协作流程。宿主不按子代理数量、投票结果、阅读配额或工具收据硬验收。SSE 观察到的 nativeSubagents 是诊断指标，不证明每个任务均正确执行。

权限配置

  • 默认拒绝；允许 read、glob、grep、list 与宿主列出的固定 Git diff / log 命令。
  • 仅主代理可调用指定的三个子代理类型；子代理不开放继续委派。
  • 格式修复代理为独立会话，所有工具均拒绝。
  • 禁止代理编辑、构建、测试、项目脚本、外部目录访问与评论发送。

“只读”指代理权限。宿主实际创建可操作的 Git 工作树，并未把整个文件系统设置成物理只读。

规则来源与优先级

  • 全局补充：安装包 resources/rules 直属 Markdown，入队时冻结，总量最多 1 MiB。
  • 仓库规则：source 根目录及变更路径祖先目录的 AGENTS.md / CLAUDE.md；缺失时回看 base，不跟随规则链接。
  • 按提示词，较近目录覆盖祖先；明确适用的补充规则覆盖仓库要求，同级冲突记限制。
  • 没有规则文件或补充规则为空属于正常情况；表达偏好不能修改 JSON 合同与固定章节。

保留哪些检查，如何修复和容错
  • 检查完整 JSON、字段类型、必需文本、枚举、数组大小、安全相对路径、正整数行号及 endLine ≥ startLine。解析输出上限 4 MiB；最多 100 条 Finding。检查不会证明行号确实对应缺陷。
  • severity 支持 fatal / major / minor / suggestion；revision 支持 source / base。tags 可空；locations、solutions、preventions 至少一项。snippet 和 example 可省略。
  • 顶层可解析时，只将无效意见交给修复器，原有有效条目不交由其改写；顶层不可解析时提供完整原文修复。仍无效或缺少内容时隔离并记录未完成。
  • 路径误带 source/ 或 base/ 前缀时，仅在原路径不存在、去掉对应修订前缀后的路径确为文件时修正。仓库确有同名目录则保留原路径；这不是完整的文件证据校验。
limitations 非空 ≠ 自动 partial。程序保留模型的 incomplete 标志；顶层无效、仍有结构错误、主会话错误或准备阶段限制会触发 incomplete，修复会话错误或修复遗漏也有相应处理。普通说明、SSE 警告和目录清理警告不会仅因存在就把完整结果判为 partial。

05

结果、异常恢复与本地存储

result 描述检视完整性与发现；status 描述任务和人工处理阶段；queuePaused 描述队列是否暂停。

条件结果 / 任务处理队列与后续动作
complete + 零意见pass；status 为 completed继续 FIFO；不会自动发表评论。
complete + 有意见findings；awaiting_confirmation继续 FIFO；用户逐条发送或不发送。
incompletepartial；有有效意见则 awaiting_confirmation，无意见则 completed有效项可人工发送；处理完仍保留 partial，不变成 PASS。
普通任务异常 / 超时review_failed；记录错误通常继续后续 FIFO；不自动重跑失败任务。
SSE / 日志 / 目录清理异常警告；不单独推翻已保存结果通常继续；若记录状态时发生存储故障，则按存储故障暂停。
进程退出未确认有可用结果时先保存；无结果时记录失败或停止暂停，保留排队项与待清理工作区；用户重试清理。
报告 / 状态存储失败不把未登记的报告当作可发布结果；已登记结果不因后续警告写入失败被撤销暂停；状态文件无法写入时至少在内存中暂停。
用户停止排队项移出 FIFO；活动任务取消后 stopped不发布中断输出；若退出仍未确认，队列仍需暂停。
评论发送失败 / 结果未知Finding 标记 failed / unknown；记录该次发送结果不自动重发评论，不因此拖停检视队列。

恢复不是重新生成

  1. 用户调用 POST /api/reviews/resume。
  2. 等待旧 worker 结束，重试进程退出确认。
  3. 检查工作区中的持久化 PID 记录，再执行待清理回调。
  4. 成功写入恢复状态后清除暂停 / fatal 标记，继续保留的 FIFO。

没有暂停时恢复是空操作；并发恢复返回 409。失败时保留暂停，不重发已有模型请求。

重启后的处理

reviewing / stopping 任务标为 stopped，尚未开始的 queued 任务保留，规则快照可恢复。原有发布中的意见恢复为结果未知，不能假定未发送。

启动检查遗留进程记录：PID 仍存活、无法确认或记录异常时暂停。只检查，不自动杀死可能被系统复用的 PID；确认进程不存在后删除标记。
