提交外层无效返回 REJECTED 并保留最近有效候选；Finding 逐项核实，无效项丢弃并反馈。最新有效候选整体替换，补读后可重新提交。最终 incomplete 或仍有丢弃项时为 PARTIAL，零条问题也不显示 PASS。取消、断流、超时或崩溃不接受候选。

PARTIAL 与发布工作流独立；报告保留简要范围限制，执行记录 diagnostics 保存过程。重复保存必须三份文件完整且一致。

放大多轮循环：不是一次把源码塞给模型

index / diff / rules→search 找线索→read 读 source / base↻ 按需继续查证→submit 全部 Findings

以上工具均带 reviewx_ 前缀。搜索只告诉模型“可能在哪里”，不算已读代码证据；引用具体行前，必须实际读取对应版本的文件。

候选 → 接受 → 可用，是三道门

SUBMITTED：收到专用工具提交。
ACCEPTED：正常终态、收据与证据均通过。
登记完成：报告文件写齐且状态事务成功，界面才可读取并决定发布。

规则写正文，接受器核证据

外置规则要求中文标题、问题描述、位置、影响、解决方案和预防措施，以及四档严重级别。接受器不解析正文骨架，也不会替模型润色；它严格核验合同与证据。

不成功的出口

情况行为与边界
MR 变化 / 材料不完整两次 MR 检查不一致、不可审变更、缺规则或必需页未读，均不生成可发布成功结果。
非法 / 冲突提交无效 changeId 或未读证据导致该 Finding 丢弃、候选标记部分完成；外层契约错误返回 REJECTED 并保留旧候选。新调用可修正或替换提交，同一 messageID / callID 改参仍致命冲突，工具输入输出均核对收据。聊天 JSON 不作回退。
取消 / 超时 / 错误 / 断流不能接受结果；取消先请求原生 abort，再有界停止本次进程。检视取消不终止独立评论发送进程。
文件写好，登记失败孤立文件没有成功状态引用，不可发布；不会自动恢复为成功。
重启 / 发送结果不确定重启不续跑检视；评论结果未知时不盲目重发，保留状态供人工核对。

数据流转

临时读取代码，长期保留结果与核验凭证。状态可以更新，成功报告保持不变。

T / S / B：三个版本，一次固定的比较

SHA 是版本的身份证。固定 SHA 后，从 Git 树和 blob 读取，不 checkout 工作树；未修改的调用方也能读取。删除读 base，重命名保留两侧路径。图中提交分叉为解释性示意。

读取与提交边界

页面最多 200 行、32 KiB（文本预算 24 KiB）；blob 16 MiB；完整 diff 与每次累计交付各 64 MiB；提交 1 MiB、100 条 Finding、单条正文 64 KiB。超限不裁剪成成功结果。OpenCode 启动至关闭共用 60 分钟预算。

任务代理采用 deny-all，仅允许六个 ReviewX 工具；拒绝 Shell、编辑和任意网络等工具。此为应用层权限约束，不是操作系统沙箱。不可审变更阻断成功；材料交付前检查敏感输入。定义见 src/server/review/result-receiver.tssrc/server/integrations/git.ts。

验证层级与完成条件

每轮改动完成时执行类型检查、lint（含导入边界）、单元 / 集成与桌面 E2E，再串行执行源码真实模型验收和完整打包验收。两次真实模型均为必执行项，无需环境开关或再次确认；会消耗模型额度，不能以此为由跳过。

入口保护范围与完成条件
pnpm test单次 Vitest 执行单元和集成目录；当前 98 + 28 = 126 项。保护固定修订、凭据 / 路径安全、提交 / 终态核验、FIFO、取消、恢复、报告与发布边界。
pnpm test:coverageV8 统计 src / app 可执行代码，排除测试、生成物和纯类型文件；仅度量单元 / 集成执行，不包含浏览器和真实模型验收。不能用总百分比代替关键模块行 / 分支核对。
pnpm test:e2e包含部分结果展示回归，单 worker，默认桌面 1440 × 900；保护页面接线、Markdown 安全、键盘 / 焦点 / 滚动及真实后端闭环。失败截图和 trace 保留，不设手机或视觉断点矩阵。
pnpm test:ai源码引擎真实模型闭环：固定合成仓库、冻结规则、多轮工具与正式结果。核对执行凭证，并人工复核生成意见是否有代码依据；进程成功不等于意见质量通过。
pnpm test:package每次构建、打包、隔离安装、检查资源与生命周期，然后无条件调用已安装引擎的真实模型验收；任一步失败即整体验收失败。脚本自动传递内部引擎路径，用户无需配置。

源码与安装包证据分别写入 test-results/acceptance/<时间戳>/，核对合同、执行记录和意见正文。记录环境、命令、结果和失败或未执行原因；技术验证与正文质量分别复核，历史通过不能替代当前验证。

详细约定：产品验收标准 · 开发与验证入口。测试数量对应本页源码基准，不是实时统计。

术语速查

MR
合并请求：希望把一组代码变更合入目标分支。
attempt
一次独立检视尝试；重新检视创建新记录，保留历史。
Finding
一条完整问题意见：等级、Markdown 正文、变更引用和证据。
scope
固定检查范围：T/S/B、变更清单与范围哈希。
hash
内容指纹，用来核对变化；不是加密，也不代表内容正确。
receipt
宿主记录的交付凭证：调用归属、已读行范围、响应哈希。
merge-base
两侧版本共同的历史基线；本实现要求它唯一。
SUBMITTED / ACCEPTED
已收到候选 / 已正式接受；之间必须完成整体核验。
FIFO
先入先出：先排队的检视先执行，与人工发布独立调度。
