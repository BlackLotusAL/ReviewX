## 最小修复与回归证明

每次连接创建独立 Undici Agent，对该检视的 HTTP 和 SSE 禁用隐式 headers/body 超时，由已有 AbortSignal 负责总时限、用户取消和清理时限。关闭连接时销毁 Agent；不修改全局 dispatcher，不增加自动重试。显式依赖 `undici@7.24.4`，其 Node 要求 `>=20.18.1`，兼容本项目的 Node 22 下限。

新增真实 socket 测试：把环境默认 transport 超时压缩到 50ms，服务实际延迟 2.6 秒返回响应头或后续响应体。没有 mock fetch 或直接构造超时异常。两个用例在修改前均以 `OPENCODE_CONNECTION_FAILED` 失败，修改后通过。另覆盖 SSE 静默等待、真实挂起请求和读取响应体时的总时限，验证服务退出、没有完成结果且未重复提交模型请求。

修复后的本地验证：18 个测试文件、129 项单元/集成测试全部通过；TypeScript、ESLint、Next.js 生产构建及 tsup CLI 构建通过。

## 复现命令和测试有效性

```powershell
pnpm test:ai:commit --repo . --commit 68fddfdbb41316514422148f7c5150879805c67b
```

若环境中的 pnpm 命令包装器不能找到 tsx，可在正常 Windows 用户环境使用同一个入口：

```powershell
node node_modules/tsx/dist/cli.mjs tests/ai/real-commit.ts --repo . --commit 68fddfdbb41316514422148f7c5150879805c67b
```

默认 `pnpm test` 不调用真实模型。此前测试能验证响应契约、错误转换、脱敏和清理，但直接 mock 超时不能证明长时间传输可用；小型真实样例也没有覆盖这次约 5 分钟的单回合边界。

真实提交没有预标注的正确答案。链路成功仅表示调查、查证、结构化输出及本地证据校验全部完成，不能换算准确率。保留现有有已知答案的正反例及质量评估入口，不用真实项目返回意见数量替代误报/漏报评价。

现有质量评估会执行样例的行为契约来验证正反例标签，但正例的 `hit` 仍通过意见正文关键词正则判断，并非逐条因果链的语义评分；`confidence` 也是模型自评。因此其“命中数”是有限样例上的启发式指标，不是生产检视准确率。本次没有更改这些评分规则，也没有重跑全部 36 次模型对照实验。
